# Re-deriving is not the same as editing. Each row was recomputed from

# be produced by anything except the layout it names. Editing a row to
# match a CHANGED layout is the defect; recomputing every row when the
# hash function itself changes is maintenance, and it is mechanical and
# repeatable from the commits. If you change the function again, do the
# same thing and say so here.

# IT CHANGED AGAIN ON 2026-09-13 AND ALL ROWS WERE RE-DERIVED, for the
# same class of reason one level along. The pattern was anchored with

# the struct and in its own NW_TYPE, left every hashed line identical
# and the suite printed ok. Un-anchored now.
